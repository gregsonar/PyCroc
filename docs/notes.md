## croc и subprocess

1. **Прогресс-бар печатается через `\r`, а не `\n`** (croc перерисовывает
   строку). Построчное чтение `readline()` слипает все обновления в одну
   строку до конца передачи. Решение: чтение чанками +
   `split_stream_chunks()` с разделителями `\r\n`/`\r`/`\n`
   ([parser.py](../src/pycroc/core/parser.py)). Нюанс: одиночный `\r` в хвосте
   буфера удерживается — он может оказаться половиной `\r\n`, разрезанного
   границей чанка.
2. **Accept-prompt печатается без перевода строки**: croc выводит
   `Accept 'file' (116 B)? (y/n) ` и блокируется на stdin. Из нарезки по
   разделителям такая строка не выйдет никогда → deadlock auto-accept.
   Решение: `CrocRunner._run()` пробует незавершённый остаток буфера на
   `ACCEPT_PROMPT_RE` после каждого чанка.
3. **stdout процесса — `DEVNULL`, не `PIPE`**: без `--stdout` croc туда не
   пишет, а нечитаемый `PIPE` при заполнении буфера — потенциальный deadlock.
4. **У ошибок croc нет единого префикса** между версиями. `ERROR_RE` ловит
   только `Error`/`error`/`failed to`; остальное покрывает fallback
   `CrocRunner`: ненулевой returncode → `ErrorEvent` из последних
   нераспознанных строк stderr.

5. **Глобальные флаги croc идут ДО подкоманды `send`**
   (`croc [GLOBAL OPTIONS] [COMMAND] [COMMAND OPTIONS] [files]`, urfave/cli).
   Глобальный флаг после `send` (например `--relay`) валит процесс с usage
   в stdout (который мы отправляем в DEVNULL) и пустым stderr — симптом:
   мгновенный exit 1 без единой распознанной строки. Обнаружено на
   acceptance-прогоне с реальным croc v10.2.7 (Task 14). Там же выяснилось:
   `--hash` — флаг подкоманды send (у приёма его нет), кривые пишутся
   строчными (`p256|p384|p521|siec|ed25519`) — «P-348» из плана не существует.

6. **croc send с piped stdin шлёт stdin вместо файлов**: наш `CrocRunner`
   всегда открывает stdin как PIPE (для ответов y/n), а croc send при
   не-TTY stdin переключается в режим `cat file | croc send` — создаёт
   `croc-stdin-*`/`croc-marked-files.txt` в cwd и вечно ждёт EOF.
   Решение: `build_send_args` всегда добавляет глобальный `--ignore-stdin`
   (приёму нельзя — там stdin нужен для подтверждений). Обнаружено на
   acceptance-прогоне Task 14.

7. **Формат прогресса v10 отличается от планового**: направление печатается
   ОТДЕЛЬНОЙ строкой (`Sending (->10.8.1.1:42767)`), прогресс начинается
   с имени файла (у приёмника — с ведущим пробелом), юниты у обоих счётчиков
   (`( 0 B/524 kB)`), скорость есть только в ненулевых обновлениях, а
   `[0s:0s]` в финальной строке отсутствует. Плюс у приёмника есть стартовая
   строка `Receiving 'file' (512.0 kB)`. Решение: `PROGRESS_V10_RE` рядом со
   старым однострочным `PROGRESS_RE` (v8/v9), `direction` в событии может
   быть пустым. Реальный захват — tests/fixtures/croc_stderr_samples.txt.

8. **Кодовая фраза передаётся через env `CROC_SECRET`, не через argv** —
   иначе она видна в списке процессов ОС (`ps`/Task Manager). Проверено на
   croc v10.2.7: при заданном `CROC_SECRET` приём работает БЕЗ позиционного
   аргумента кода, отправка — БЕЗ `--code`. `build_send_args`/
   `build_receive_args` кода в argv не содержат; `CrocRunner` кладёт его в env
   через `croc_secret_env()`. Env=None (нет своего кода) → наследуется
   окружение родителя, croc генерирует фразу сам.

## Textual

9. **`Widget._size` — внутренний атрибут** (объект `Size` компоновщика).
   Поле `self._size` в наследнике ломает рендер загадочным
   `'str' object has no attribute 'region'`. Именовать поля специфичнее
   (`_target_size` в OverwriteConflictModal).
10. **`Label.renderable` не существует** (Textual 8) — содержимое в тестах
   читать через `str(label.render())`.
11. **`Button` глушит повторный клик** пока играет его active-эффект (~0.3 с):
   два `pilot.click()` подряд по одной кнопке — второй молча теряется.
   В Pilot-тестах между кликами нужен `await pilot.pause(0.4)`.
12. **Уведомления в тестах** проверяются только через приватный
   `app._notifications` — публичного API перечисления нет.
13. **Worker + `finally` + размонтирование**: если панель удалена посреди
   передачи, `query_one` в finally кидает `NoMatches` (причём `is_mounted`
   ещё `True`, когда дети уже удалены) — финальные UI-обновления оборачивать
   в `try/except NoMatches`, запись в историю делать безусловно.
14. **Кеш меток `Tree`**: `refresh()` не перерисовывает изменённую метку узла —
    ключ line-кеша включает счётчики `_updates` узлов в path строки. Решение:
    `self.root.refresh()` (bump `_updates` у root, который входит в path всех
    строк) + `self.refresh()` — см. `MultiSelectDirectoryTree._refresh_labels`.
15. **`screen.focus_next` в BINDINGS контейнера тихо не срабатывает** (Textual
    8.2.8): биндинг с неймспейсным действием на не-фокусируемом контейнере не
    выполняется, без ошибки. Решение: локальное действие
    (`action_focus_next_field` → `self.screen.focus_next()`).

## Python и типизация

16. **`qrcode.print_ascii` использует `\xa0`** (неразрывный пробел) для
    пустых модулей QR; для mypy нужны стабы `types-qrcode`.
17. **Метод `list` в классе затеняет `builtins.list`** в аннотациях других
    методов того же класса (mypy valid-type) — писать
    `builtins.list[...]` ([history.py](../src/pycroc/storage/history.py)).
18. **`.py`-заглушку нельзя exec-нуть напрямую** (особенно на Windows):
    `CrocRunner` запускает пути с расширением `.py` через `sys.executable`.
