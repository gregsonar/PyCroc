# План: поддержка `croc update` из интерфейса PyCroc

Статус: запланировано (не реализовано). Автор задачи: обновление под croc v11.

## Цель

Дать пользователю проверить и (где это возможно) применить самообновление croc
прямо из вкладки Settings, не уходя в терминал. Фича опирается на подкоманду
`croc update`, появившуюся в croc v11.5.

## Что делает `croc update` (croc v11.5)

- `croc update --check` — только сообщает, доступна ли новая версия. Вывод:
  `croc vX.Y.Z is available (current: vA.B.C).` либо `croc vX.Y.Z is up to date.`
- `croc update` — спрашивает подтверждение `(y/N)` и заменяет исполняемый файл.
- `croc update --yes` — то же без вопроса (для скриптов). Есть алиас `croc upgrade`.
- Croc сам скачивает архив релиза и контрольную сумму по HTTPS, проверяет
  SHA-256, разворачивает бинарь рядом, запускает его для сверки версии и лишь
  затем заменяет текущий файл одним `rename`. При любом сбое остаётся старый croc.

### Важные ограничения (влияют на UI)

- Croc заменяет только **официальную standalone-установку**, помеченную
  инсталлятором. Для установок из пакетных менеджеров (Homebrew, Nix, Scoop,
  **Chocolatey**, Conda, MacPorts, Termux, FreeBSD ports, системные пакеты,
  `go install`) croc **отказывается** обновляться и печатает команду обновления
  через соответствующий менеджер. Это не ошибка — это ожидаемый ответ.
- На **Windows** заменить запущенный исполняемый файл той же безопасной
  операцией нельзя, поэтому croc указывает на страницу загрузки релиза, а не
  обновляется на месте. Основная целевая машина PyCroc сейчас — Windows +
  chocolatey (см. [docs/notes.md](../notes.md), `_kill_tree`), то есть в типовой
  установке самообновление будет **недоступно**, и UI обязан это внятно показать,
  а не выдавать за сбой.

## Ограничения со стороны PyCroc

- PyCroc запускает croc через `asyncio` subprocess и читает stderr (см.
  [runner.py](../../src/pycroc/core/runner.py)). `croc update` без `--yes`
  ждёт ввод `y/N` в stdin — интерактивный диалог. Решение: спрашивать
  подтверждение **своей** модалкой PyCroc, затем звать `croc update --yes`.
- `CrocRunner._run` защищён флагом `_running` (один кан/процесс передачи).
  Update — это отдельная короткая операция, не передача; она **не должна**
  делить этот guard с send/receive (иначе update во время передачи молча
  бросит `TransferInProgressError`, а update — законное отдельное действие).
  Вынести в отдельные методы `check_update()` / `run_update()` со своим,
  более простым чтением вывода (у update нут `\r`-перерисовки прогресса).
- Замена бинаря на диске — необратимое действие над окружением пользователя.
  По правилам PyCroc это требует явного подтверждения пользователем (модалка
  «Обновить croc с vA на vB?»), даже что croc и сам спросил бы.

## Дизайн UI (вкладка Settings)

1. Рядом с текущей проверкой версии добавить кнопку **«Проверить обновления»**.
   - Запускает `croc update --check`, парсит вывод, показывает одно из:
     - «Доступна vX (сейчас vY)» + активная кнопка «Обновить»;
     - «Актуальная версия (vY)»;
     - «Самообновление недоступно: установка через <менеджер>» с командой,
       которую напечатал croc (для chocolatey/Windows — типовой случай).
2. Кнопка **«Обновить»** (видна только если апдейт доступен и установка
   eligible): открывает модаль подтверждения; при «Да» запускает
   `croc update --yes`, показывает прогресс/итог, по успеху перечитывает версию
   через существующий `check_binary()`.
3. Все сетевые/дисковые ошибки croc показываются как предупреждение, приложение
   не роняется (тот же принцип, что и с отсутствующим croc).

## Парсинг вывода update

Отдельные паттерны (не смешивать с парсером передачи):

- `^croc\s+v?(?P<version>\d+\.\d+\.\d+)\s+is available\s+\(current:\s*v?(?P<current>\d+\.\d+\.\d+)\)`
- `^croc\s+.*\bis up to date`
- Сообщение про пакетный менеджер / Windows-загрузку — распознавать по ключевым
  словам и показывать текст как есть (формулировки croc могут меняться между
  версиями — не завязываться жёстко).

Ветку выбора паттернов держать в новом модуле (напр. `core/update.py`), чтобы
не раздувать `parser.py`, заточенный под stderr передачи.

## Вне области

- `croc ssh` (шаринг терминала, croc v11.4) — не относится к передаче файлов и в
  PyCroc не добавляется.
- Автоматическое/фоновое обновление — только по явному действию пользователя.
