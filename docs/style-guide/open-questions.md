# Открытые вопросы

Вопросы из первой версии style-guide **закрыты** ответами владельца и внесены в
документы (ветвление, PR по умолчанию, отсутствие трейлера, авто-хвост в имени
ветки, ruff+mypy, эмодзи, SemVer, расположение README/CONTRIBUTING, судьба
конспектов тестирования). Ниже -- то, что осталось решить **по этому конкретному
проекту**; это не пробелы в правилах, а конкретные действия/решения.

## 1. Настройка баг-трекинга для PyCroc -- РЕШЕНО

Расположение трекера по умолчанию -- **`.claude/bugs/`** (решение владельца).
Режим (single-log `BUGLOG.md` vs index `INDEX.md` + `BUG-*.md`) определяется при
заведении первого бага по скиллу `bug-report-tracker` (см.
[04-tasks-and-bugs.md](04-tasks-and-bugs.md)). Пока багов нет, каталог можно не
создавать.

## 2. Историческая `tmp/manual-testing-notes.md` -- РЕШЕНО

Оставляем **как есть**: исторические находки (пункты 1-14) не мигрируем в трекер
и не переносим в `docs/`. Это черновик процесса, уже почти полностью закрытый.

## 3. Первый промоушен `dev -> main` и тег `v0.1.0`

Релиз 0.1.0 сейчас живёт в `dev`; в `main` не смёржен, тега `v0.1.0` нет. По
правилам это **штатное состояние** (в `main` мёржит только человек, по своему
решению). Вопрос чисто операционный: когда владелец даёт команду на первый
промоушен `dev -> main` и простановку тега. Действие пользователя, не пробел в
правилах.

## 4. Корневой `CONTRIBUTING.md` -- РЕШЕНО

Создан в корне как **тонкий маршрутизатор** (quickstart + гейт + поток веток +
памятка со ссылками), без дублирования правил. Единый источник истины остаётся
`docs/style-guide/`.
